# 更新记录、版本树与汇总

## 1. 更新记录与版本树

```
docs/changelog/
├── v0/
│   ├── v0.1/
│   │   ├── v0.1.0.md        初始版本
│   │   ├── v0.1.1.md
│   │   └── SUMMARY.md       次版本自动汇总
│   └── v0.2/
│       ├── v0.2.0.md
│       └── SUMMARY.md
└── summaries/               手动汇总
    ├── v0.md
    └── v0.1.0_v0.2.0.md
```

第一层按主版本，第二层按次版本，文件为单次更新记录。

### 单次更新记录

```markdown
# v0.2.0

- 日期：2026-11-02
- 对应提交：标签 `v0.2.0`（比较基准：`v0.1.1`）
- 摘要：一句话，同时用于 CHANGELOG.md

## 新增
## 修改
## 修复
## 移除
## 不兼容改动

## 涉及的功能
BAK-01、HIS-05（功能编号见 bonfire-test 的功能清单）

## 涉及的需求
REQ-0xx

## 涉及的文件
<文件列表>

## 更新的项目专属 skill
- `bonfire-cli`：无需更新
- `bonfire-test`：功能清单新增 ……
- `bonfire-update`：无需更新

## 测试情况
- 是否测试：是
- 测试范围：按功能（……）/ 全量
- 结果：Rust ……、CLI 用例 ……、前端 …… 通过，0 失败
```

没有内容的分类整节省略。

### CHANGELOG.md

只作总览，每个版本一行，新版本在上：

```markdown
# 更新记录

- v0.2.0 · 2026-11-02 · <摘要> · [详细记录](docs/changelog/v0/v0.2/v0.2.0.md)
- v0.1.0 · 2026-10-11 · 初始版本 · [详细记录](docs/changelog/v0/v0.1/v0.1.0.md)
```

## 2. 版本汇总

### 自动汇总（次版本）

每生成或修改一份更新记录，就重新生成所在次版本目录的 `SUMMARY.md`：按变更分类整理；同一功能的多次改动合并为最终结果并注明来源版本；列出各版本的测试情况，未测试或未通过的单独标出。

### 手动汇总

用户说“汇总一下更新记录”时询问范围：

| 方式 | 示例 | 文件名 |
|---|---|---|
| 主版本 | 整个 `v0` | `v0.md` |
| 区间（含两端） | `v0.1.0` 到 `v0.2.0` | `v0.1.0_v0.2.0.md` |
| 列举 | `v0.1.1`、`v0.2.0` | `v0.1.1+v0.2.0.md` |

规则同自动汇总；写入 `docs/changelog/summaries/`，同名文件已存在时询问是否覆盖；指定版本不存在时列出实际存在的版本。
