### 性能与资源（文档 10.1）

基准测试 `tests/bench/main.rs`（release 构建，数据按固定种子生成在临时目录中）：

```bat
cargo test -p bonfire-tests --release --test bench -- --ignored --nocapture --test-threads 1
```

| 指标 | 目标 | 结果 |
|---|---|---|
| 增量扫描：200 款游戏（1000 个文件）无变化 | < 3 秒 | 0.09 秒 |
| 全量扫描：200 款游戏，不用修改时间判断、重新计算全部文件的哈希 | < 30 秒 | 0.12 秒（文件在系统缓存中） |
| 备份吞吐（哈希 + 压缩，多线程）：64 个 8 MB 不可压缩文件 | ≥ 200 MB/s | 约 1260 MB/s |
| 参考：单个 256 MB 文件（分块串行处理） | — | 约 270 MB/s |
| 存储效率：未变化的文件再次备份 | 零新增 | 只新增快照与清单 0.3 KB |
| 快照元数据（快照 + 清单，5 个文件） | < 10 KB | 平均约 640 字节 |
| 托盘常驻内存（release 程序关闭窗口进入托盘 60 秒后） | < 80 MB | 主进程工作集 41.6 MB（专用 13.4 MB）；关闭窗口时 WebView 随窗口释放，不占内存 |
| 参考：窗口打开时 | — | 主进程 41 MB，WebView2 6 个进程合计工作集约 390 MB |

托盘内存在隔离的 release 构建上测量（独立的程序标识与临时数据目录，不影响本机安装的篝火）。

## 二、用户验收（请在本机安装新版本后逐项确认）

安装：运行 `build.bat` 生成的 `target\release\bundle\nsis\Bonfire_0.1.0_x64-setup.exe` 覆盖安装（`data` 保留）。

> 注意：历史清理删除快照后无法撤销。建议先在“立即清理…”的预览中确认数量，或先用一个不在意的游戏试。

| 需求 | 验收步骤 | 结果 |
|---|---|---|
| REQ-001 其余平台 | 设置 → 存档备份 → 扫描的平台中有 Ubisoft Connect、EA app、Xbox、Battle.net；“发现”页扫描后列出这些平台已安装的游戏（本机已识别出守望先锋） | ☐ |
| REQ-007 运行保护 | 游戏详情 → 更多 → 游戏程序…，看到安装目录或添加游戏的程序；游戏运行时恢复被阻止、备份前提醒 | ☐ |
| REQ-008 自动备份 | 打开“退出游戏后自动备份”（游戏库工具栏的自动备份菜单或设置页），玩一会儿游戏后退出，约 10 秒后出现“游戏已退出，已自动备份”的提示，详情页新快照标为“退出游戏后自动” | ☐ |
| REQ-009 历史清理 | 设置 → 历史清理：调整保留规则后保存，“立即清理…”先显示将清理的快照数与可释放的空间，确认后清理；带标签的快照、每条路线最新的快照仍在；之后“校验仓库”完好 | ☐ |
| 托盘内存 | 关闭窗口留在托盘，任务管理器中 Bonfire 的内存低于 80 MB | ☐ |
