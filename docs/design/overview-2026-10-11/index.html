总览页设计方案

2026-10-11 · 待确认后开发（版本 0.3.0）。下面先是方案说明，然后是页面效果图（静态示意，数据为示例），最后是数据来源与需要确认的问题。

一、这个页面要回答的问题

打开总览，玩家想知道的只有一件事：“我的存档现在安全吗？如果不安全，我要做什么？”其余信息（大小、记录）是用来回答“为什么”和“发生过什么”的。

所以页面从上到下按“结论 → 要做的事 → 依据 → 历史”排列：

  1. 存档的三道防线：磁盘上的存档 → 篝火仓库 → 远程，每一段是否接上，一句话结论。
  2. 待处理：失败、提醒、建议，每条一个直接解决的按钮，可以“稍后提醒”。
  3. 存储（左）与截图与磁盘（右）：占用了多少、哪些游戏最占空间、可清理多少；一键对比截图、一键收集 / 写回。
  4. 操作记录：按天列出备份、恢复、同步、清理、截图等，可筛选、搜索，失败的可以直接跳到处理。

二、视觉方案

记忆点只有一个：三道防线。“磁盘 → 仓库 → 远程”是篝火独有的备份链，用三个大数字和两段连线表示：连线实线绿色表示这一段完全接上；琥珀色虚线表示有缺口（如有游戏没备份）；红色虚线表示断开（如远程同步失败）。不用常见的“四个统计卡片”首屏。

其余部分保持安静：沿用应用现有的颜色、字体与圆角；待处理列表用左侧 4 px 色条区分严重程度，不用整行红底；数字统一用 Bahnschrift 等宽数字。

窗口底色 smoke
面板 surface
主色 ember：操作、提醒
moss：已接上
amber：有缺口
danger：失败、断开

五、需要你确认的问题（括号中为建议）

#问题建议
1总览在导航中的位置，以及启动后先显示哪一页放在导航第一项，带“需要处理”的红色数字；启动后仍显示游戏库（总览按需打开）。也可以改成启动显示总览
2操作记录存在哪里、要不要同步到远程只存在本机 data\activity.jsonl，保留 180 天，不同步（里面有本机路径）；卸载时随 data 一起处理
3存档要不要“一键写回磁盘”不提供。写回存档就是恢复，会覆盖磁盘上的存档，只在游戏详情中预览后逐个恢复；总览中存档只提供“全部备份”
4失败时是否弹出 Windows 系统通知同步失败、自动备份失败时弹出（篝火窗口不在前台时），设置中可以关闭；同一个问题重复失败只通知一次
5“一键与磁盘对比”什么时候运行打开总览时在后台对比一次（10 分钟内不重复），也可以点“重新对比”；对比只读磁盘，不写入

确认（或修改）以上 5 点后，按 0.3.0 开发：后台汇总与操作记录 → 总览页界面 → 批量截图对比 / 写回 → 系统通知，每步带测试。
