## 1. 项目概述

本软件（中文名「篝火」，英文名 **Bonfire**）是一款桌面端游戏存档备份工具：自动扫描本机各平台的游戏存档，判断哪些有更新，由用户选择备份哪些，并以 Git 的快照模型保存完整历史，支持随时恢复到任意版本。

**目标**

- 覆盖 Steam、Epic、GOG、Ubisoft Connect、EA App、Xbox/Microsoft Store、Battle.net 及模拟器/独立游戏，开箱即用。【已完成】
- 增量、去重存储：未变化的文件不重复占用空间。【已完成】
- 每次备份（快照）可写备注，恢复前可预览差异，恢复操作本身可撤销。【已完成】
- 同时备份游戏截图，与存档历史关联。【新增，REQ-014，已完成】

**范围**：首版仅 Windows 10/11（64 位）；架构预留 Linux（Steam Deck/Proton）与 macOS。云同步、多设备合并列入后续版本，不在首版范围。Linux / Steam Deck 支持经用户确认推迟到后续版本（REQ-013）。

**术语**

| 术语 | 含义 | 对应 Git 概念 |
| --- | --- | --- |
| 游戏（Game） | 一个被识别的游戏条目，可含多个存档位置 | 仓库（repo） |
| 存档位置（SaveLocation） | 磁盘上的一个目录/文件通配或注册表键 | 工作区中的路径 |
| 快照（Snapshot） | 某一时刻一个游戏全部存档的完整状态 + 备注 | 提交（commit） |
| 对象（Blob） | 按内容哈希存储的文件内容 | blob |
| 清单（Tree） | 快照中的文件路径 → 对象哈希列表 | tree |
| 分支（Branch） | 一条快照线，如「主线」「二周目」；界面中称“路线” | branch |
| 标签（Tag） | 永久保留、不被清理的重要快照，如「Boss 前」 | tag |
| 主存档 | 每台电脑自己的主线路线（新增，U-41） | — |
| 管理方式 | 存档和截图 / 只管理存档 / 只管理截图（新增，U-10） | — |

**关键约束**

- 备份和扫描对存档目录**只读**；只有恢复操作写入存档目录（截图写回原位置属于用户主动的恢复类操作）。
- 任何恢复都不得丢失数据：被覆盖的当前状态先入库。
- 仓库位置可配置（安装版默认 `<安装目录>\data\repo`），可放在网盘同步目录中；放在网盘时建议开启仓库加密。

## 3. 系统架构

系统分为表现层、应用服务层、引擎层（存档发现 + 版本存储）和操作系统四层；GUI、CLI、后台守护共用同一套服务与引擎，引擎层不感知界面。实现：Rust workspace（`bonfire-core` 版本存储、`bonfire-discovery` 存档发现、`bonfire-app` 应用服务层、`bonfire-cli` 命令行）+ Tauri 2 桌面应用（React / TypeScript）。

| 模块 | 职责 | 状态 |
| --- | --- | --- |
| 扫描服务 | 调用适配器与规则库得到存档位置，再做变更检测（第 5 节），输出每个游戏的状态 | 已完成 |
| 备份服务 | 对用户勾选的游戏逐个读取文件、分块入库（多文件并行）、生成快照并写入备注 | 已完成 |
| 恢复服务 | 生成保护快照 → 进程检查 → 写回文件 → 记录操作，支持撤销 | 已完成 |
| 历史服务 | 快照列表、差异对比、分支与标签管理、备注修改与搜索、删除快照与分支 | 已完成 |
| 清理服务 | 执行保留策略、标记-清除垃圾回收、`fsck` 校验 | 已完成 |
| 后台守护 | 监听游戏进程退出与定时器，触发自动备份；托盘常驻 | 已完成 |
| 截图服务 | 收集截图、相册与回收站、与磁盘对比（新增） | 已完成 |
| 导入导出服务 | 历史包、合集包、zip、下载存档导入（新增扩展） | 已完成 |

## 4. 存档发现

### 4.1 平台适配器【REQ-001，已完成】

| 平台 | 游戏清单来源（实现） | 存档常见位置 |
| --- | --- | --- |
| Steam | 注册表 `HKCU\Software\Valve\Steam` → `libraryfolders.vdf` → `appmanifest_*.acf` | `Steam\userdata\<steamId3>\<appId>\remote`、文档、AppData |
| Epic | `%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests\*.item` | `%LOCALAPPDATA%\<Game>\Saved\SaveGames` |
| GOG Galaxy | 注册表 `HKLM\SOFTWARE\GOG.com\Games` | 文档、AppData |
| Ubisoft Connect | Windows 卸载程序登记 `Uplay Install <ID>` + 启动器目录（规则库 `<root>`） | `Ubisoft Game Launcher\savegames\<userId>\<gameId>` |
| EA App | Windows 卸载程序登记（卸载程序位于 `EAInstaller` 下） | 文档、AppData |
| Xbox / MS Store | `%LOCALAPPDATA%\Packages\*\SystemAppData\wgs` 所在的应用包；规则库按包名匹配 | `wgs` 容器，整体备份 |
| Battle.net | Windows 卸载程序登记（卸载命令中的 `--uid`，跳过启动器本身） | 文档、AppData |
| 模拟器 / 独立游戏 | 用户手动添加 | 用户指定 |

与原文的出入：Ubisoft / EA / Battle.net 的清单来源由启动器私有文件改为 Windows 卸载程序登记（决策 M4-1a）；Xbox 不调用 `Get-AppxPackage`（决策 M4-1b）。

### 4.2 存档规则库【REQ-001，已完成】

规则库有三个来源，优先级从高到低：用户自定义规则；社区规则库 Ludusavi Manifest（内置快照，联网时按 ETag 增量更新）；启发式探测（结果标记「待确认」，确认后转为自定义规则）。路径变量与 glob 匹配、`save` / `config` 标签、注册表存档导出为 `.reg`、单个游戏超过 2 GB 提示，均按原文实现。

### 4.3 游戏信息自动获取【REQ-001，已完成】

按原文：本地数据优先、联网补充、结果缓存，失败或离线不阻塞。提供者 steam-local → steam-store（简体中文）→ IGDB → SteamGridDB；图片缓存为 WebP；手动修改的字段加锁；可一键关闭联网获取。

### 4.4 截图来源【新增，REQ-014，已完成】

Steam `userdata\<账号>\760\remote\<AppID>\screenshots`；Windows 游戏栏 / Xbox 应用的“捕获”文件夹（按文件名中的窗口标题对应游戏）；为游戏添加的截图文件夹；公用截图文件夹（按子文件夹名或文件名对应）；对应不上的放入“未识别的截图”。只读取，不写入截图目录。

## 5. 变更检测算法【REQ-002，已完成】

按原文实现：先用大小与 mtime 快速筛选，变化的文件再计算 BLAKE3 确认；racy-git 处理；强制校验；并行扫描并逐游戏推送结果。

被占用的文件【REQ-012】：备份时读取文件用共享读模式；文件被游戏独占锁定时，默认不备份该游戏并提示（自动备份推迟到游戏退出后），设置开启后用 VSS 卷影复制读取（需要管理员确认）。

## 6. Git 式版本存储模型【REQ-003–006、009，已完成】

按原文：内容寻址对象库（BLAKE3、zstd、FastCDC 分块去重）、refs、notes、reflog、SQLite 索引；写入顺序 Chunk → Blob → Tree → Snapshot → ref，崩溃只留下无引用对象；仓库文件锁。与原文的出入：对象按类型分目录存放（`objects/chunks|blobs|trees|snapshots/`）。

- 6.4 分支：从旧快照恢复后继续游玩，下次备份时询问创建新分支或移动当前分支，默认创建新分支；恢复到某条分支的最新快照时接回这条分支。每台电脑记住自己的主存档路线（U-41）。
- 6.6 清理：保留策略决定压掉哪些快照，子快照改接到保留的快照上；从所有引用与 30 天内 reflog 出发标记-清除。默认只清理自动生成的快照；带标签的、各分支最新的、当前所在的、撤销恢复要用到的快照永远保留。packs 推迟。
- 6.7 加密【新增，REQ-011】：随机数据密钥 + AES-256-GCM，数据密钥用密码经 Argon2id 派生的密钥加密存进仓库配置；对象、备注、操作记录与游戏列表加密，索引移到本机；截图、分支与标签名不加密。

## 7. 数据结构与数据库设计【已完成】

按原文：对象库与 refs 是唯一事实来源；SQLite `bonfire.db` 可由「重建索引」恢复，游戏配置另存 `games.toml`。快照触发方式扩展为 `manual | auto-exit | auto-timer | auto-change | pre-restore | import`。新增表：`game_metadata`（原文 4.3）、`screenshots`、`shot_settings`、`game_processes`。游戏 ID 规则按原文，新增 `ubisoft-`、`ea-`、`battlenet-`、`xbox-<包名>` 前缀。
