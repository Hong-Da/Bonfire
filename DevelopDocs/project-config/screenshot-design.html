游戏截图备份：实现方案

2026-10-09 · 已确认：按推荐项，并补充 S3 可定时备份（每天、每周等）、S1 增加 Windows Xbox 截图。

本机实际情况（只读查看）

来源位置本机能否对应到游戏
Steam 截图（F12）<Steam>\userdata\<账号>\760\remote\<AppID>\screenshots\*.jpg，另有 thumbnails\ 和 screenshots.vdf（拍摄时间、分辨率、所属游戏）6 个游戏，89 张，26 MB精确（按 AppID）
Windows 游戏栏（Win+Alt+PrtSc）%USERPROFILE%\Videos\Captures，文件名如 Minishoot 2026_7_18 0_02_36.png5 张按文件名开头的游戏名匹配（较可靠）
游戏自带截图 / 其他工具（NVIDIA、Epic 等）各不相同—由用户为游戏添加“截图文件夹”

总体设计

  • 截图不进存档快照：单独作为每个游戏的“相册”。否则每拍一张截图都会产生新的存档快照，恢复存档时还会把截图写回去。
  • 存储复用对象库：截图作为普通文件对象入库（BLAKE3 去重、原子写入），已入库的不再重复存储；JPG/PNG 本身已压缩，不再做 zstd/分块压缩（直接存放，省 CPU）。
  • 只增不减：磁盘上删掉的截图，备份里仍保留（这正是备份截图的意义）；可在界面里手动删除备份中的截图。
  • 与存档时间线关联：每张截图按拍摄时间归到“拍摄时所在的快照区间”，时间线上的篝火旁显示该段时间的截图缩略图（“这次存档前后拍的截图”）。
  • 绝不写入截图目录：截图“恢复”只做导出到你选的文件夹，不写回 Steam 目录。
  • 数据结构：索引数据库新增表 screenshots(game_id, blob, taken_at, source, original_path, width, height, size, added_at)；缩略图（WebP，320px）放在 data/cache/shots/，可随时重建。仓库中另存 albums/<game>.jsonl，数据库丢失时可重建。

需要你确认的决定

S1 截图来源

  1. Steam 截图 + Windows 游戏栏 + 每个游戏可手动添加截图文件夹推荐
  2. 补充：Windows Xbox 截图（游戏栏与 Xbox 应用都保存在系统“捕获”文件夹，位置可被用户修改，读取系统设置中的实际位置）已确认
  3. 只备份 Steam 截图
  4. 只备份手动指定的文件夹

Steam 和游戏栏覆盖了大多数情况，且都能可靠对应到游戏；其他工具的位置五花八门，交给手动添加。

S2 默认是否开启

  1. 全局默认开启，每个游戏可单独关闭推荐
  2. 全局默认关闭，每个游戏单独开启

截图体积不大（本机 89 张 26 MB），开启的价值高；设置里显示每个游戏截图占用的空间。

S3 何时备份截图

  1. 随存档一起：每次备份（手动、退出游戏自动、定时）时顺带收集新截图；游戏库“检查更新”时提示新截图数推荐
  2. 补充：可设置定时备份截图——每天 / 每周（选星期几）/ 每 N 小时，或关闭；后台运行时执行已确认
  3. 只在详情页手动点“备份截图”

S4 存储方式

  1. 原图入库（不重新压缩），缩略图另存缓存推荐
  2. 转为 WebP 有损压缩后入库（省约 30–50% 空间，但不是原图）

S5 界面

  1. 详情页新增“截图”标签页（按时间分组的网格，点开大图，可多选导出/删除）；时间线快照旁显示该时段截图缩略图；快照详情里列出“这段时间的截图”推荐
  2. 只做“截图”标签页，不与时间线关联

S6 导出与分享

  1. 截图可单独导出（选中的或全部，zip / 文件夹）；导出历史包（.bonfire）时可勾选“包含截图”，默认不包含推荐
  2. 历史包总是包含截图

CLI

bonfire shots <游戏>                 列出已备份的截图
bonfire shots sync [<游戏>...]        收集新截图（backup 时自动执行）
bonfire shots export <游戏> -o <目录|zip> [--since 日期] [--snapshot 快照]
bonfire shots rm <游戏> <截图ID>...
bonfire game shots-dir add|rm <游戏> <文件夹>
